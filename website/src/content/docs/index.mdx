## The platform

Nexor is **four desktop apps** that share **one source tree** and speak
**one signed `.nexor` package format**:

<CardGrid>
  <Card title="🟦 Nexor Studio" icon="pencil">
    The IDE — code editor, form designer, sheet editor, BPMN 2.0 process
    designer, builder. Writes `.nexor` packages to disk.
  </Card>
  <Card title="🟪 Nexor Core" icon="setting">
    The backend HTTP server — package registry, audit log, entity REST
    CRUD, RPC for `[ServerOnly]` activities, persistent workflow engine.
    Has its own GUI for environment-variable settings.
  </Card>
  <Card title="🟧 Nexor Command" icon="approve-check">
    The admin console — registers packages with Core, deploys, rolls back,
    audits.
  </Card>
  <Card title="🟩 Nexor Flux" icon="rocket">
    The end-user runtime — installs packages from Core, runs Activities,
    Forms, and Processes locally with transparent server-side RPC.
  </Card>
</CardGrid>

## The develop → publish → run loop

```
   Studio ──build──▶ .nexor ──register──▶ Core ──deploy──▶ Core (live) ──fetch──▶ Flux
                                  │                                    │
                                  └─────── Command  ──audit log─────── ┘
```

Studio writes `<project>/dist/<id>-<version>.nexor`. An administrator
running **Command** picks the file and registers it with Core. Command's
admin UI then deploys the pending row to live, after which Flux can
catalog → install → run it.
